## Findings

1. **Exact request bytes pass.** `exact_job_spec.json` is 1,693 bytes and independently hashes to `437dd1af38b91713c464b0b8c8430765ddf0fdd3c4fb592f51afa817daeb076b`. 2. **Authority caps pass.** The request pins project `project-160ccb20-98ab-4538-a847-01d1f83d5b0f`, workspace `ws-9dcc0e1f-80a4-4af2-bc2f-0e352e7b17e6`, H100 LCG `lcg-71b971a7-5bdd-4798-b5ba-08f1eabde49e`, and resolved spec `7166bd2e-6cbe-4bd9-be38-762d11003e7f`. Existing bounded resource evidence binds that pool/spec combination to one eight-GPU H100 SXM 80 GB node. One node × eight GPUs × 0.5 hour is exactly the four-GPU-hour cap.
3. **Scheduler safety fields pass.** `max_running_time_ms` is exactly the schema-required string `"1800000"`; `auto_fault_tolerance` is false; `fault_tolerance_max_retry` is zero; both success/failure reservation durations are `"0"`; notification/troubleshoot are false; task priority is zero. There is no retry loop in controller code.
4. **Launcher and environment pass.** The command is only `/usr/bin/bash` plus the previously approved `run_qualification.sh` path. The exact environment contains the reserved run ID `qualification-20260912-01-7bef6cf8-fda4-46b9-84ff-d7ca4fe5b892`, nonce `d75f2419e63b1c052beda405b5c7d963`, manifest `92fbf9afe7d0c7b47829337639dae54debddc8e9409c0903f30358aa75aa656c`, exact formula-derived GPFS receipt path, four offline/unbuffered flags, and nothing else. No operator-provided job ID, image digest, or workflow-inner sentinel is injected.
5. **Image identity is honest.** The request uses the proven reference-job value `SOURCE_PRIVATE` for `docker.sii.shaipower.online/inspire-studio/relay2:v2`. The strict future receipt binds known scheduler catalog row `image-7330d118-df9d-4e2e-82b1-c2543e831eb4`; `observed_image_digest` remains strictly null because qz exposes no content digest and CreateJob cannot pin one.
6. **One-shot ordering passes.** `record_and_call_once` exclusively writes and fsyncs `request-attempt.json` before invoking its runner exactly once. Every nonzero result, invocation failure, timeout, missing/invalid/multiple-ID response, or later publication failure leaves that attempt marker in place. A repeat reaches the exclusive write first and fails as `submission_already_attempted` without another runner call.
7. **Generic API rejection is terminal.** A future nonzero qz result is reported as generic `createjob_failed`, but this does not authorize or suggest retry: the already-written attempt marker blocks a second call. The authorized policy remains stop/no-resubmit for rejection or ambiguity.
8. **Returned identity is not the operator run name.** On exit zero, the controller validates JSON and requires exactly one `job_id` field matching the strict `job-<UUID>` form. The `qualification-...` request name cannot satisfy that type. The parsed response ID alone becomes the admission record and receipt ID; missing, invalid, or multiple IDs fail closed.
9. **Admission precedes receipt publication.** After parsing the real returned ID, the controller exclusively persists `admitted-job.json`, then constructs and validates the payload's actual `ControllerReceipt`, then publishes it by a same-directory temporary file and atomic no-clobber hard link. Any post-admission failure raises `AdmittedJobError` containing the exact new job ID so an operator can monitor or stop only that job.
10. **Payload receipt compatibility passes.** The controller imports and validates against `scale.experiments.nonlatent_iclr.qualification.controller_receipt.ControllerReceipt`, not a parallel permissive schema. Project/pool/spec/image/catalog/shape/caps are literals; run ID, nonce, manifest, exact request hash, and real job ID are dynamic bindings; extra fields are forbidden; image digest is null.
11. **Root PASS update is compatible by design.** The current authorization and `controller-state.authorization_sha256` both reflect historical reservation hash `e7af34a994015297c7eff4e209fff6029cdc47de8c6f3456a7bc108539de0f82`. Submission deliberately does not compare the updated authorization file hash to that historical value. It reparses the current file and enforces every immutable tuple/cap field as a literal, plus `jobs_submitted == 0`, then separately requires current `preflight_verdict == "PASS"` and exact root confirmation. A temporary PASS/status-only update rebuilt byte-identical request bytes; changing an immutable field was rejected. The authorization entry in `input-hashes.sha256` is therefore historical after the root edit and is not a live controller gate.
12. **Independent CPU evidence passes.** The designated suite ran with `PATH=/nonexistent`, `PYTHONDONTWRITEBYTECODE=1`, and cache-disabled pytest: 18/18 passed in 1.07 seconds. Thus no qz executable was resolvable; the only CreateJob runner exercised was the fake. A supplemental all-temporary fake-runner sequence proved attempt-before-call, exactly one call, returned-ID propagation, admission-before-publication, repeat refusal, generic-rejection no-retry, and ambiguous-response no-retry without touching GPFS.
13. **No previous submission evidence exists.** `request-attempt.json`, `admitted-job.json`, and the exact GPFS controller receipt destination are all absent, including symlinks. The authorization records zero submitted jobs/zero GPU-hours; controller state is `NOT_SUBMITTED`; reservation count is exactly one with null job ID. The prior single dry-run remains non-admitting and was not repeated.
