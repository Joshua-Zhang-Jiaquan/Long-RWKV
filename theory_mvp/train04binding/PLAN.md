## Motivation and scope

The original prompt names variables and specifies output order, but its answer canvas contains adjacent anonymous bit/mask tokens. All four phase700 models nearly solve direct fixed-coordinate constraints while failing multi-pair parity, and their prior N2 competence is not retained. These facts motivate testing whether binding public variable names to answer positions is a bottleneck; they do not establish that explanation.

Render the answer canvas as ` bit3=[MASK]; bit1=0; ...`, taking every label from the existing public Output order line. Labels, equals signs and separators are clamped context tokens. Only the original bit-value slots are corrupted, predicted or scored. Preserve coordinate order, gold bits, mask draws, public A/C, oracle marginals, information-set policy, train/dev/test structure split, and original N8 target posterior. No solver-generated answer, latent intermediate, canonical reordering or additional target-derived information is supplied. This is deterministic redundancy of existing public information, with longer input and additional computation.

The encoder and packer are in lrwkv_evidence/train04binding/core.py. The existing serial wrapper supports noncontiguous gathered target positions. CPU tests check gold-independent serialization, unchanged visible/masked values and supervision, clamped scaffold tokens, separate-document equivalence and gradient flow. These tests do not qualify real GPU kernels or establish learning performance.
